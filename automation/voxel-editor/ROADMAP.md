# 从离线扫描到可摆放、可细化的房间

先让用户面对一个容易理解的房间。墙、地面和桌面保持平整，大物体有范围和名字；用户可以像放置游戏一样画出方块、拉高、移动、命名，再让 AI 接手有限区域。后续操作都在已确认的米制结构上延续。

工作区上层的“原始简单的想法/原始想法.md”把最终用途放在适老化沟通、品牌选型和交付。本路线先验证它最基础的一环：用户是否能看懂真实尺寸的空间、表达摆放意图，并以少量操作修改方案。简单几何、语义和米制坐标会给后续商品、AR 和工程接口留出空间，但现在不提前承诺净空、施工精度或商品必然适配。

## P1 先交付什么

第一条演示线是 Office 2 → 平整墙地面与语义粗框 → 选桌面 → 拖出 3×2 格矩形 → 拉高 2 格 → 命名“台灯底座” → 移动/复制 → 保存重开。Office.zip 虽然没有导出 PLY，也应进入同样的粗编辑场景。

页面布局、视角控制和处理顺序参考原版 Viewer；同时保留原版 Layout 的独立 SVG 平面路线，帮助用户理解占地、选择与摆放。它应保留米制轮廓/墙洞口、带旋转占地、尺寸/近似面积、图例及平移/滚轮缩放/适配，之后增加同场景的编辑交互，不能只用三维相机俯视代替。查看、选择、创建模式分离，避免拖动镜头时误创建。底层保存米制几何，不把当前格号当成真实坐标。

P1 不需要真实 AI 才能完成。先用人工编辑和确定性命令验证操作闭环。没有 AI 服务时也必须能完整查看、摆放、保存和撤销。

## P2 的“变细”如何判断对错

用户指出实验 6 只有格线后，P2 按 [网页接入路线](WEB_VOXEL_INTEGRATION_PLAN.md) 与 [体素不变量](VOXEL_EDITOR_V2.md) 推进：`P2-00 框架/单位适配 → P2-06 精简工作台/统一事务 → P2-05 实例与候选边界 → P2-01 真占据 → P2-03 游戏式编辑/归属修正 → P2-02 局部层级 → P2-04 性能验收`。openPlan3D 的本地 Bridge 是接缝，体素 API 尚未接通；不能逐格塞家具数组。

界面保留本地保存、2D/3D、对象树、属性和撤销，以“查看 / 物体 / 格子”组织工具；高级家具、材质和复杂结构收起，PDF/CAD/写实渲染等拆为真正可选加载模块。先将自动保存从工具栏提升到编辑会话，再替换工具栏。体素与 plan 共用有序命令/撤销和原子保存，不将海量 cells 放入上游全量 JSON 历史。启动和网络基线从 P2-06 开始采集，性能收益以实测为准。

20→10→5 cm 时，桌面仍是同一平面、洞口仍为空洞、物体米制位置与尺寸不变。P2 必须有真实占用格/父子层级与确定性拆格；只改 gridStep、吸附距离或多画格线仍属于 P1 的交互模数，不得据此把 P2 标为完成。局部到 2.5 cm 只作用于完整父格集合，框选吸附后显示实际范围。RoomPlan 的非整格尺寸允许裁短边格，渲染、查询、拾取和体积遵循同一有效形状，不能通过吸附暗改测量值。

局部建模可以用小 Box、Cylinder 等简单几何拼出柜门、冰箱门、花洒等部件；先证明范围、父子层级和撤销正确，再接模型。粗略 HTML 示例只说明几何组合的可能性，不作为主界面或工程基线。

占据表达不自动提供物体实例边界。先保留 RoomPlan 的对象种子与人工归属，再按结构平面、点/超体素和可用照片证据修订；接触的物体不能靠连通域强行合并。每件对象保留局部有效占据，世界粗格只索引候选 owner，真实拾取/碰撞再查询有效形状。孔洞随物体移动/90°旋转，不能从粗框重填。类别、实例、未知/冲突和物理占据分层保存，无法可靠分开的地方允许框选、拆分、合并与重新归属。更重的多视角 AI 分割是可替换离线提案来源，不进入实时刷格循环。

## P3–P4 的 AI 边界

衍生 Skill 放在实验 8 自己的 .agents/skills/voxel-room-edit/。按[原版继承清单](BASELINE_REUSE.md)完整复制 scan-to-threejs 为不可改的 upstream 快照，记录逐文件来源/哈希和 MIT 许可；保留坐标约定、测量优先、照片/扫描证据核对、同视角对照和项目布局原则，再增添体素命令与局部/批量细化规则。原版参考目录保持只读。

AI 接口返回受约束的结构化提案。请求带场景版本、选区/物体 ID、锚面、米制范围和锁定项；不接受模型自由执行 JavaScript。未选区和锁定承载面不能被偷偷改写。局部细化、覆盖、清空和批量操作都能预览并撤销。批量按物体或局部块逐件生成，失败保留粗版。

## 暂缓自动执行

用户已明确排除 openPlan3D iPhone 端。本轮只做网页编辑器和现有离线输入；手机采集改造、手机互通、往返、AR 与实时同步均不属于当前实施路线，也不在 P4 后自动启动。[手机入口评估](IOS_CAPTURE_ASSESSMENT.md) 只作历史研究，除非用户重新提出，否则后续代理不开展这条线。

商品规格匹配、净空承诺和水电施工图仍需新的验证条件。TASKS.json 的 deferred 列表显式禁止自动提前开始。

完整任务、依赖和验收条件见 TASKS.json；当前状态运行 taskctl.py report 查看。
