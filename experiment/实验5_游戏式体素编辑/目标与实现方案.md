# 实验 5｜像游戏一样布置房间的体素编辑器

状态：**目标与实现方案**。这一轮只有文档；网页编辑器、本机 AI 服务、衍生 Codex Skill 和 AR 回看尚未实现。实验 4 仍用于核对扫描证据，不应把它的表面体素当成实验 5 的初始可编辑模型。

## 一句话目标

打开扫描包后，用户先看到一间**横平竖直、带语义、能操作的粗房间**：平整的地面与墙面、门窗开口、桌椅等大件的粗范围和桌面承载面。像放置游戏一样，用户可以在地面、墙面、桌面框出矩形，向外拉伸成任意 a×b×c 格的方块组，给它命名和摆放。全局变细或局部变细都以这套**已确定的结构与语义**为父层；AI 可以只细化选区，也可以在布局完成后逐件细化所有已标注对象。扫描网格始终可作对照，但**调细格子不会重新照抄 PLY 的凹凸**。

首个用户可理解的演示：打开 Office 2 → 看见平整房间与“桌子／椅子”粗框 → 在桌面拖出 3×2 格、向上拉 2 格并命名“台灯底座” → 改全局密度，底座仍在同一米制位置且桌面仍平 → 选择底座让 AI 细化 → 再对所有已标注对象请求批量细化，预览后接受或撤销。另用 Office.zip 验证：没有导出的 PLY 也可以进入同样的粗编辑场景。

## 先把扫描归类，再生成平整基底

本项目的扫描包已有 RoomPlan 房间结构。实验 2 的 converted.json 提供米制地面多边形、墙段、开口，以及物体类别、中心、尺寸、朝向；实验 4 的 scan_room.ply 是融合深度的扫描证据，**已经**在房间坐标中。实验 5 采用原版约定：XZ 为地面、Y 向上、单位米；两个独立扫描会话不自动拼接。原版 scan-to-threejs 从测量结构出发，再参考扫描与照片迭代建模；它没有一键输出可编辑体素家具。

| 类别 | 初始表达 | 编辑中的作用 | 必须避免 |
| --- | --- | --- | --- |
| 地面 | 按 RoomPlan 多边形生成平整承载面，保留凹进轮廓 | 放置与框选的水平锚面 | 用房间外接长方形填掉凹进或门口 |
| 墙、门窗 | 沿实际墙段生成平整立面，保留开口；可按主方向归为约四面墙 | 墙面放置锚面和锁定结构 | 强行把六段墙压成四片实心墙；把窗填满 |
| 桌子 | 保存 RoomPlan 旋转包围盒及“桌子”语义，另给出盒顶的平整桌面锚面 | 桌面放置、选中、改标签 | 把整盒叫作已测得的实心桌子，或凭空捏造桌腿 |
| 椅子、柜子等 | 有类别的粗包围盒或用户修订的方块组 | 可移动、旋转、改名的物体 | 把包围盒误说成自动识别出的精细外形 |
| TSDF／原始 PLY | 可开关的原始扫描／半透明叠加层；第二包 PLY 先按 inroom 过滤 | 校对平面、尺寸和不确定处 | 作为每次加密网格的几何生成器 |
| 未识别区域 | 标记“待确认”，允许用户框选并命名 | 人工补充语义 | 视为已观测的空处或保证净空 |

初始平面以 RoomPlan 为主。扫描点在对应墙／地面／桌面附近可用于**有界的平面拟合与差异提示**：先限定在语义区域内，只接受方向一致且有足够覆盖的拟合；证据不足或偏差明显时保留 RoomPlan 粗平面，标记待核对。绝不把扫描细碎表面直接替换为默认墙面或桌面。桌面高度取粗盒上表面作为初值，并明确标记“推断”；不把它当施工尺寸。真正的墙厚、桌腿、柜门和未扫描物体，等证据或用户编辑再补。

## 两种截然不同的“变细”

**1. 密度变化，是确定性的重表达。**房间交互格默认 20 cm，可切 10／5 cm；选中的对象或区域可继续局部细化到 2.5 cm。父格拆成子格时，从连续米制平面、盒、用户方块和已接受的局部细节重新采样。平面仍平、直角仍直、门窗仍为空洞；对象的米制中心、尺寸、朝向、标签和锚面 ID 不变。原有 RoomPlan 尺寸不一定是整格倍数，边缘允许裁短显示格，不能因吸附而悄悄改掉测量值。用户**新画**的 a、b、c 是当前格子的正整数数量，其米制长度在创建时确定；之后改密度只改显示格数，不改变实际大小。

**2. 几何细化，是有范围的建模操作。**用户选择一个物体或三维框选区域，指定语义与期望部分，如“把这个粗框细化成台灯底座”。局部细格只在选区内生成，记录父格、细格、来源和候选版本。AI 可输出小方块组或受约束的基础几何，但不得挪动房间坐标、已确认的总体尺寸、支撑／挂点、锁定面，或偷偷改未选区域。候选与粗版并排或切换预览，接受后仍可撤销。原始 PLY 可以协助观察，不能决定生成形状。

“细化全部”是第二种操作的**批量编排**：在用户摆好并标注物体后，按对象和局部块逐个生成候选，让相邻块共享边界信息，显示每件成功、失败和待确认的状态。成功候选可以作为一组接受与撤销，失败项保持原样。地面、墙面、桌面等承载面继续作为锁定的平整基底；AI 可以在其上加受约束的部件与装饰，但不能让承载面重新长成扫描噪声。这借鉴 VoxLution 的粗到细与分块上下文思路，**不声称复现该论文模型，也不依赖其权重**。

## 查看与游戏式操作

后续页面独立设在实验 5，借鉴原版 Viewer 的主体画布、侧边控制、斜视／俯视／侧视、视角复位，以及“规则结构／扫描／叠加”切换。默认显示平整的结构层和有语义的家具粗框；扫描层默认不遮挡编辑。侧栏显示来源、名称、米制尺寸、所属承载面、当前格尺寸、锁定状态和不确定提示。结构、扫描证据、用户放置和 AI 候选使用不同颜色及图例。

操作分为查看、选择、创建三个模式，避免鼠标拖动同时旋转视角和画方块。创建时先选地面、墙面或桌面；射线落到该锚面上，拖出矩形并显示 a×b，再沿面的法线拉伸到 c 格，实时预览和吸附。地面／桌面向上拉，墙面向室内拉；数值面板可精确改 a、b、c、名称及离承载面的距离，允许之后自由移动或关闭吸附。确认后成为**一件**可选、可移动、可复制、可编组的物体，而非逐格填写标签。Esc 取消未提交的操作，删除、清空、AI 接受都进入同一撤销／重做历史。物体位置以连续米制变换保存，不用切换格尺寸后的整数格号充当唯一坐标。

“清空房间”有明确边界：清除或隐藏可编辑的扫描推断家具和用户摆件，包括随桌子一起消失的桌面锚面；保留地面、墙、门窗、锁定构件与原始扫描证据。已经锁定的物体列在预览的“保留”清单中。整个操作是一条可撤销命令，绝不删除原始 ZIP、PLY 或 RoomPlan 记录。清空后如果要在桌面布局，必须先恢复或新建桌子。

## AI 接法与命令边界

首版真实模型通道规划为**本机服务调用 Codex CLI＋实验 5 衍生 Skill**；未来换模型 API 时保持相同的场景命令契约。衍生 Skill 以后放在本项目自己的 .agents/skills/voxel-room-edit/，复用原版 scan-to-threejs 的坐标、证据和同视角比较原则，但另写“语义平整化、方块编辑、局部／批量细化、校验与撤销”的规则。**本轮只写方案，不创建 Skill，也不修改原版参考目录。** Skill 是代理的执行指导，网页调用还需要独立的本机服务；不能把 Skill 文件当作网页内的模型接口。

场景保存建议分成不可改的来源引用与可编辑派生状态。请求包含 sceneRevision、用户指令、操作范围／选区 ID、允许使用的承载面、语义标签、物体米制范围和锁定项；首版仅传必要结构 JSON，不把整包照片或扫描网格默认送给模型。AI 只返回结构化操作提案，例如 place_box、rename、refine_region、refine_all、clear_furniture。每个操作带目标 ID、锚面 ID、米制参数、局部格尺寸、来源及简短说明；不得返回自由执行的 JavaScript 或未经验证的整屋替换。服务校验场景版本、坐标有限性、选区边界、锁定项和命令类型，再交给场景编辑器应用。

AI 既能接手**初始布局**，也能在人工布局后继续细化。例如“在桌面放一个台灯底座”只用桌面锚面生成方块组；“在这面墙上布置两层架子”使用墙面锚面与离地高度；“清空房间”只生成清除家具的变更清单；“把已标注的家具都细化”触发逐件批量候选。这是对较早“只能人工摆放”设想的扩展；用户仍能逐件调整、锁定、撤销，AI 不把自己的摆法当作扫描事实。

按已选定的风险分级：无冲突的新增放置可直接应用，但必须立即可撤销；与现有物体相交、局部覆盖、批量细化和清空家具先列出变化并预览，用户接受后才提交。对“这里没扫到”显示未知提示，不把它伪装成可安全放置的净空。服务失败、输出不合格式或场景版本已变时不修改当前场景。批量细化逐件报告结果，保留失败对象的粗版。

## 实现顺序与完成线

1. **结构化输入**：读取两包已转换的 RoomPlan JSON，得到平整地面、墙段／开口、语义粗框与桌面锚面；用实验 4 的扫描网格做切换对照，不反向写原始包。验证第一包无导出 PLY 时同样能建立粗场景。
2. **编辑器**：先实现原版风格的查看面、来源切换、框选拉伸创建、命名、移动、撤销和派生场景保存／导入导出。用纯函数实现格子重采样，确保 20→10→5 cm 切换后平面、洞口和米制摆放不漂移。
3. **细化层**：实现父子格和局部候选预览；先用确定性拆格验证“只改密度不改形状”，再允许 AI 在选区内生成新细节。增加逐件批量编排，不用一次模型调用改写整间房。
4. **AI 与 Skill**：再创建衍生 Skill 和本机 Codex 服务，以同一结构化命令接口执行放置、选区细化、批量细化与清空。用隔离的只读输入调用代理，所有实际改动由编辑器校验和提交；模型 API 迁移只替换生成端。

验收场景：① 第一包无导出 PLY 仍出现平整墙地面和语义粗框；② 第二包显示扫描对照，但桌面从 20 cm 切到 5 cm 后仍是平面，不恢复扫描凹凸；③ 在桌面画 a×b×c 方块并命名，切密度后米制位置与尺寸不变；④ 局部 AI 细化不改变未选区；⑤“细化全部”逐件预览，不移动用户摆放；⑥ AI 清空仅影响可编辑家具，撤销后恢复。测试保留原始证据与派生状态的来源标记，不用截图漂亮程度代替几何和交互检查。

现阶段不承诺自动从 PLY 分割并命名所有家具、真实商品尺寸保证、净空保证或 AR 重定位。AR 回看在布局和坐标保存稳定之后另做实验。
