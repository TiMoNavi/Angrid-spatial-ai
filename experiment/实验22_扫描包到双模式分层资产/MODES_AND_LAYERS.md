# 两种模式与分层约定

这是处理结果的显示合同。实验 22 输出资产与显示预设，尚未新增浏览器页面。两种模式是同一间房、同一米制坐标下的观察方式，切换模式不需要重新解释或重采样原扫描。

## 模式 A：扫描证据／诊断

大致画面是可旋转的室内扫描，叠加薄墙线、家具框和低透明度观察体素。检查“实物扫到了哪里、RoomPlan 如何理解、哪里仍有争议”。核心预设有 **9 个显示层**：

| 层 | manifest ID | 内容与用途 |
|---|---|---|
| 1. 房间局部原 PLY | `raw-lidar-ply` | 原始三角网格裁到房间后显示；保留扫描噪声和缺口 |
| 2. RoomPlan 房间 | `roomplan-structure` | 墙、地面轮廓与门窗开口的测量先验 |
| 3. 家具 OBB | `furniture-obb` | Apple 识别出的有朝向粗框，可能错标或漏掉物体 |
| 4. 原 PLY 表面格 | `scan-surface-grid` | 扫描表面经过的规则格，不表示实心家具 |
| 5. 分类家具表面格 | `furniture-classified-grid` | 沿用“大件平整家具表面体素”名称；仍是观察表面，不能当作完整补建 |
| 6. 归属冲突格 | `conflict-grid` | 多个物体等归属规则冲突，等待复核 |
| 7. 未归属观察格 | `unknown-grid` | 尚未解释的扫描，不直接等于杂物、噪声或空闲空间 |
| 8. 家具扫描切片 | `furniture-slices` | 分类后保留的原始面片，常有缺失且不封闭 |
| 9. 切片 AABB | `furniture-aabb` | 面片实际覆盖范围；不能当作整件家具的真实边界 |

此外共用两层推断辅助资产：`clean-structure-grid` 平整结构体素、`furniture-corrected-grid` 家具平面规则修正格，供模式 B 使用。它们不计入上述 9 个证据层。

## 模式 B：AI 模型／体素编辑资产

大致画面是横平竖直的薄层房间壳与规整家具，可在 AI 实体模型和原生格子之间切换；需要时叠加扫描核查。核心组织为 **6 个显示组**：

| 组 | 资产 | 视觉与含义 |
|---|---|---|
| 1. 平整结构体素 | `clean-structure-grid` | 依据 RoomPlan 生成地面、墙面和开口；推断模型，非扫描毛刺复刻 |
| 2. 家具几何修正格 | `furniture-corrected-grid` | 保留既有平面规则，提供便于摆放的几何参照 |
| 3. **AI 命名实体模型** | `reconstructed-model` → `reconstructed.glb` | 独立保留的实体层，部件按 `instanceId::partId` 命名，可单独显示 |
| 4. AI 原生家具体素 | `model-voxel-grid` → `voxel-occupancy.json` | 从与 GLB 相同的整数格计划生成；统一家具层内按实例和部件选择 |
| 5. 扫描支持／冲突覆盖 | `model-evidence-overlay` | 区分同格支持、补建专属格、冲突与邻格证据 |
| 6. 扫描参考 | 原 PLY；有真实产物时可换 TSDF | 用于对照，不与建模结果混为“已识别真值” |

GLB 和体素是同一候选的两种表达，通常交替显示，避免实体和格子完全重叠遮挡。生成模型层不会替换模式 A 的分类家具观察格。也不会给沙发、椅子、桌子分别增加永久图层；使用稳定实例 ID 选择即可。

模型几何始终 `model-inferred`、`reviewState=unreviewed`、`ownerAcceptanceBlocked=true`；证据覆盖层为 `comparison`。AI 可以根据照片补腿、柜门、连续侧面等结构，但仍要保留补建依据。同格原面只能提供空间支持，不能自动证明它属于某件家具。

## 层数如何计数

上述 **9 层 / 6 组是显示预设**，彼此复用资产，不能简单相加成 15 个独立文件。机器 manifest 还记录可选产物和不可直接渲染的证据索引：

- 扫描模式有 21 条资产记录：15 条可渲染类型槽位、6 条数据索引/账本（包含平面 JSON 与 SVG 预览）；槽位是否可用由本次产物决定。
- 模型完成后有 25 条记录：在扫描记录上增加 GLB、模型格、证据覆盖和 AI 候选平面足迹；原扫描模式 manifest 单独保留。
- Living room 实测扫描模式 **11 个可用渲染资产 + 6 个可用数据资产**，完成模型后为 **14 + 7**。TSDF、深度显示点、高斯、杂物候选未生成，不显示为可用。

平面图数据以 floor-plan.json 的原版 RoomLayout 兼容字段为权威，floor-plan.svg 只作同源预览。家具 objectRefs 与 objects 逐项对齐。模型成功后，floor-plan.model-candidates.json 才记录从命名模型占据格投影的 X/Z 足迹，保持 model-inferred、unreviewed，不会替代原来的 RoomPlan 盒或家具观察体素。

照片索引、原始深度索引、实例候选账本、源面分配账本是数据资产，不作为漂浮在房间里的几何层。集合为空的家具 OBB、切片或 AABB 也应显示不可用原因。

## 可选层与坐标

| 可选资产 | 本实验当前行为 |
|---|---|
| 深度投影点 | 原始帧和机位可保留；尚不生成可显示点云 |
| TSDF 融合网格 | 不执行融合；没有真实文件时 `available=false` |
| 高斯泼溅 | 不执行重建；没有真实文件时 `available=false` |
| 杂物候选体素 | 默认不计算；未归属不能自动冒充杂物 |

原始源面序号属于原始 PLY；局部显示 PLY 的面顺序不能反向顶替。所有显示层以 `room-local-m` 配准；照片和原始深度索引保留采集坐标说明。GLB 与模型格还携带 plan/model/source/transform 哈希，避免把另一次扫描的同名房间叠进来。

## 默认叠放与透明度

显示器应尊重 manifest 的 `renderOrder`、`visual`、`available`，按下列原则实现：

1. 原扫描／真实 TSDF 作背景，结构与家具格填充初始 **10%**，加强格线和选中轮廓。TSDF 真实可用时可单独以 **100%** 作为扫描参考；本次无 TSDF，降级到原 PLY。
2. 结构采用冷青色，分类家具暖金色，平面修正格浅绿色，AI GLB／原生格薄荷青色，未归属淡紫色，冲突珊瑚粉色，OBB/AABB 最后画线框。
3. 半透明层 `depthWrite=false`，保留深度测试；用 `polygonOffset` 减少重面闪烁。简单排序不能解决所有透明交叉，密集部位需局部剖切或所选对象 x-ray。
4. 一次启用一个主要高密度表面层。不要提供一键全选所有密集层的默认操作；原扫描、不透明实体、表面格全开会遮挡且影响性能。
5. 相机保留自由三维旋转；俯视／正视只作为检查视角。模式预设定义资产组织，具体交互、线宽、剖切和材质仍由编辑器实现。

`renderOrder` 是显示顺序，不是物理堆叠或碰撞优先级。家具落地、桌面支撑、用户新放格的占据关系需由编辑器的体素文档与碰撞规则处理，不能从透明度或颜色推导。
