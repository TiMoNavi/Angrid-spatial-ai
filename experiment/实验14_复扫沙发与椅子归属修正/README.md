# 实验 14：复扫沙发与椅子归属修正

## 当前问题

Office 2 复扫在实验 13 完成独立导入后，用户指出：未归属观察体素仍过多，房间中可见的大沙发未被识别；中央椅子只有部分表面进入家具分类，其余落在未归属。实验 13 的原始导入、派生 v1、TSDF 与 Edge 页面是本实验只读基线，不覆盖旧扫描或现有平面修正。

已确认的代码门槛：现有分类器只对 RoomPlan objects 中的家具建立 OBB 候选。复扫 objects 为 1 椅、3 桌、1 storage，没有 sofa，因此缺席的大件无法进入该候选流程。这不等于 PLY 没扫到沙发。椅子表面问题仍需按源三角面 ID 分解，不能仅凭混色体素判断该格属于椅子还是相邻桌子。

苹果的 [RoomPlan 类别](https://developer.apple.com/documentation/roomplan/capturedroom/object/category-swift.enum/sofa) 本身包含 `sofa`；它此次没有输出这个实例。RoomPlan 只交付识别出的参数化物体，不能从结果倒推出漏检的唯一原因。蓝色覆被、遮挡、视角和扫描质量都只能列为可能因素，不能据此归咎于用户或设备。照片与 PLY 源面证明这个位置有可见扫描表面，但还不能证明完整沙发轮廓。

## 不依赖 RoomPlan 清单的补救路线

1. 把 RoomPlan 框当已知物体线索，另从未归属 PLY 源三角面提出候选。用照片点击或射线命中作语义种子，在同一米制坐标内寻找邻接面；先排除墙、地、开口和已知家具框，再限制区域、法线和高度。不能把整个连通片一键命名为沙发，因为它可能连到墙、地或别的物体。
2. 将照片直接命中的核心、由空间和拓扑扩展的表面、与已有家具冲突的面分别显示，均附源面 ID 和待复核状态。这样用户能接受、拒绝或重新框选某一部分；原 unknown 总层和旧 owner 账本始终可切回。
3. **切分后再体素化**：各候选源面分别投到同一个米制格网，保留同位多 owner 和观察证据。之后才对确认的物体建立编辑用 OBB／平整几何；缺扫侧面、腿和靠背只能作为独立的推测层，不能伪装成 PLY 实测。
4. 椅子同理逐面处理。桌椅重叠区域先显示冲突，不因一个体素格同时触及椅子和桌子就强行改归属。将来可增加“画一笔正样本／负样本”和分割模型建议，但最终提升为家具语义应有可撤销的人工确认。

当前 `prepare_candidates.py` 钉住这份 Office 2 复扫的源哈希、照片命中面和空间范围，只证明这条补救路线在本案例可执行；它不是对所有房间自动识别沙发的通用模型。尤其无照片种子的邻近连通片只能作为低置信候选，不能并入已确认家具。

## 当前导入入口的边界

编辑器顶栏仍有原版平面项目／RoomPlan JSON 导入；它的 ZIP 分支只读取恰好一个 room.json。3D Model Anything 的完整 iPhone 导出包含 Room/manifest.json、Room/rooms/room-0.json、PLY、深度与照片，没有这个 room.json。把它丢给顶栏不会生成扫描图层，现会明确拒绝并指向 [实验 13 的离线导入命令](../实验13_家具补形与未归属细分/README.md)。页面的“恢复完整实验工程”只恢复当前扫描身份下的平面与用户体素设计，扫描资产仍须已在本机准备。

当前 Office 2 复扫依次由实验 13 的 import_office2_rescan.py 执行 base、depth、fusion、classify，再由本实验 prepare_candidates.py 生成待复核层；后者钉住该包的源哈希、照片锚点和 ROI，换一份扫描不能直接复用。这些是本地脚本调用原版 scan-to-threejs 工具，不是页面已自动调用 Codex 的 skill 流程。

## 实验边界

- 保留实验 9 与 13 的 derived-v1 原始分类账本和全部源面 ID；新结果写入 office-2-rescan/derived-v2，并由实验 14 的独立查看器加载。
- 原始 PLY、RoomPlan、TSDF、平整墙地和桌面几何修正不变。观察证据、候选归属、AI 脑补建议、用户设计盒各有独立图层。
- 用户指出“沙发”作为语义线索可引导候选定位，但几何区域必须来自真实源面与照片；未观察到的靠背、腿和侧面只可进入另外的可选脑补层，不作为本轮实测修复。
- 新候选先复核，保留 unknown 总层与原归属，允许一键关闭实验 14 的覆层返回实验 13。粗格同位不抹去多 owner 冲突。

## 执行顺序

1. 对新 PLY 的 unknown 做源面连通和空间组件分析，借照片与已知家具框确定沙发候选的源面支持、语义与未覆盖范围；避免把墙、窗帘或桌子拼到沙发。
2. 对唯一椅子逐面核对原始类别、OBB 全顶点裁剪、结构优先、与长桌多 owner 冲突及连通片门槛。明确“椅子前面”在家具总层中的真正 owner。
3. 只生成可追溯的 derived-v2 候选层与剩余 unknown 复核层；不改原 v1 账本，不把误扫/未扫和实测家具补面混作一层。
4. 在独立查看器里叠加沙发候选、椅子边界／冲突诊断、剩余 unknown；用颜色、线框、半透明和逐件隔离核对，并在 Edge 回归 2D/3D、原家具编辑和扫描开关。

完成标准：新分类候选能定位用户所说两处问题，源面守恒、哈希与房间坐标通过；旧层可完整切回；照片或源面不足的区域标未决。具体统计与截图在 QA_REPORT.md 记录。
