决策日期：2026-11-14。本文是三份独立调研的综合实施约束，**不是已实现功能清单**。实验 6 保留作平整房间和人工方块交互的检查点；下一轮从新的实验 7 开始，不继续给实验 6 多画格线。

依据：[openPlan3D 源码评估](openplan3d-integration-assessment.md)、[实时体素技术调研](realtime-voxel-research.md)、[VoxLution 迁移评估](voxlution-transfer-assessment.md)。任务及状态以 TASKS.json / STATE.json 为准。

最新范围与接线以 [网页精简与体素接入路线](WEB_VOXEL_INTEGRATION_PLAN.md) 为准：不考虑 openPlan3D iPhone 端，只读现有离线扫描；先接精简工作台、统一事务/保存，再做真实体素。本文保留体素不变量，不把研究当实现。

## 先纠正当前缺口

实验 6 的对象是连续米制 Box，`gridStep` 控制吸附和表面线条。它已有框选拉伸、摆放、命名和撤销，但不能回答“这个位置是哪一格、是否占用、由谁占用、删掉后保存的是什么”。因此它只是编辑模数原型，尚未实现用户要求的体素网格。

真正的体素模式要有实际占据数据。关闭线条以后，选格、填充、挖空、碰撞查询、保存和局部细化仍须工作。表面合并成一个 Mesh 是渲染优化，不得把格子数据一起合并掉。反过来，也不应为每个格子创建一个家具对象或一个 UI 组件。

## 数据结构：几何真值、占据和显示分开

1. **证据层只读**：RoomPlan、PLY、照片、相机、session transform。没有 PLY 也能进入编辑。未扫描不自动解释为可放置的空地。
2. **语义和参数层**：平面、洞口、承载面、粗包围盒、用户或 AI 的部件树；稳定 objectId、名称、来源、锁定和米制变换。扫描家具包围盒仅表示推断范围，不能自动声称它是一块实心物体。
3. **体素占据层**：统一世界坐标/轴向/步长族；对象局部 gridOrigin、整数格索引、层级、chunk 与有效裁剪定义形状，持久保存 placementStep/pivot，不随变细漂移。世界 lattice 仅为多 owner 候选索引，允许承载面引入固定相位偏移。占据、归属、语义、未知、锁定与版本是真实编辑数据，不是从 Mesh 反推的临时缓存；冲突不能用最后写入者静默覆盖。
4. **渲染层**：从有效占据生成可见面；格线、悬停单元、选区和剖切为叠层。2D 视图既保留平面设计，也能查看当前高度的占据切片；两者读同一状态。

体素域统一用米，openPlan3D 的平面模型用厘米。唯一适配层负责 XZ↔plan XY、米↔厘米、中心↔底高、弧度↔度、旋转符号、楼层高程和网格原点。UI 不允许散落 `*100`。相邻墙不完全正交时保留测量来源及偏差，不偷偷把整个扫描旋转/拉直；明确显示当前轴向化基底及其推断性质。

第一版统一二次幂步长族：20→10→5→2.5 cm，各对象有稳定的局部网格。0.73 m 桌面可作新对象的局部建格平面，不向世界 20 cm 格点偷偷抬高；显示当前工作平面，不能把不同相位假装无缝全球格网。90°旋转保持局部格点，移动/reanchor只改姿态和世界候选索引，不重采样局部孔洞；全局变细逐对象拆格。原扫描任意角度代理保留测量，轴向化草模显式标 inferred。边界单元可被理想结构体裁短，保留精确裁剪与来源；查询/面拾取/体积/碰撞共用有效形状。supportPlane是零厚度锚面，结构占据另有标注厚度及来源的solidDomain。

承载面保存origin/u/v/normal，首版编辑frame限房间轴向。锚定对象的世界姿态由anchorFrame×localPlacementPose唯一推导，phase不另存第二真值；attachmentPoint/pivot不因挖孔重算。格数/体积按对象局部有效叶子计，不能按跨过多少世界候选格重复计数。首版雕刻后缩放直接拒绝，避免属性面板从Box重建形状。

推荐先做稀疏 chunk + TypedArray，比较 16³ 与 32³；不是先做复杂神经场或把整房填成细密 JS 对象。chunk 中按需分配实际数据，不为整屋空气逐格建 Mesh。初版可用实例化确认数据到交互闭环，随后用可见面剔除/greedy meshing。每次编辑只更新脏块及必要邻块；大重建放 Worker，旧 revision 的 Worker 结果不得覆盖新编辑。

**层级一致性规则**：细化区由子格替代父格，不双重占据或重复计体积；粗细边界共用确定坐标并正确剔除内部面。局部修改是权威补丁，不能在下次全局拆格或重表达时被粗 Box 覆盖。降密度只合并完全等价的子格；已有孔洞、标签差异、裁剪或部件细节不能通过最大池化被抹掉，可保留局部细层或明确拒绝有损合并。

## 物体边界：先保留身份，再求几何分割

用户追加的问题是另一项核心缺口。体素化回答“哪里占据”；实例分割回答“属于哪一件”；几何表面回答“边界究竟在哪里”。三者需要关联，不能以一种代替另外两种。给所有椅子一个 `chair` 类别也不能区分两把椅子。相触的桌/墙会连成一片，一张桌子的几条腿也可能被扫描成互不连通的片，所以连通域不能直接充当物体身份。

本地源码审计发现，输入其实已有一部分身份信息：原始 RoomPlan 带 `identifier`、置信与属性。只读原版 `scan-to-threejs/scripts/bundle_to_room.py` 的对象转换（约 154–166 行）输出只保留 category/center/size/rotY/front；实验 6 `scene-model.mjs` 的初始化（约 155–167 行）再按索引创建 `roomplan-N`。这丢掉了扫描原生的实例关联。应在新实验导入适配器修复，不回改原版，也不把恢复 ID 宣称为获得精确物体外形。原始 PLY 的 face class 是类别，不是实例；类别不能恢复两把同类椅子的身份。

推荐按成本递增处理：

1. **保留已有实例**。优先读取原始 RoomPlan 的标识/OBB/类别/置信/父关系；converted 数据仍可作对照，但新派生模型保存 `sourceInstanceId`、编辑 `objectId`、来源版本和对应变换。用户放置的对象在创建时就有独立身份，不需要再从整个房间连通域里猜。
2. **轻量几何分配**。先按已确认平面和开口约束分离结构，再以对象范围为种子对点/超体素做受限分配，结合位置、法线、颜色、接触关系。OBB 只限定候选，不把盒内一切都归给该物体；桌面薄板附近也不能无条件扣掉所有水平面。证据不足保留 unknown，多种归属保留 conflict。
3. **人工校正始终可用**。在剖切/透视里框选或涂选，支持拆成新对象、合并对象、重新归属、冻结边界。移动对象只移动它自己的格子/部件，接触对象不跟走。拆合进入同一撤销历史；改类别不会改变实例身份。
4. **较重 AI 只给候选**。具备配准 RGB-D、内参、位姿时，可考虑 2D mask 多视角提升和融合到 3D；缺深度时的遮挡、薄结构和多视角身份关联必须单独处理。单图 3D 生成是在补全/创造几何，不能冒充从原始扫描准确拆分。详细选型、输入闸门和许可见实时调研的实例边界章节。

接触面两边继续保留不同 `instanceId`；表面合并要将 owner/语义作为合并键。空间占据 union 可用于粗碰撞，但不作为对象保存和编辑的唯一真值。不同实例落入同一粗格时保留多候选或进一步局部细化，不能任选一个 owner 导致另一个对象被吞掉；粗格混合不等于真实几何碰撞。粗框、推断填充、实测表面与用户设计用不同状态表示，“是否占据未知”与“已占据但归属未知”分开存储，未知区域不承诺真实净空。

最小边界验收是“贴墙的柜子可单独选中并移走，墙留下；两把相触椅子可拆开；同一桌子的分离腿仍属同一桌子；同一粗格多 owner 保留候选并精确查询，真实重叠才报冲突；拆/合/改归属后保存重开一致”。自动分割质量另以带人工标注的本机小样本评估，不能用包围盒看起来合理或单纯连通域数量充当精度。

## 用户看到的完整操作

打开离线房间 → 默认显示平整且可定位单元的体素结构、带语义的家具代理 → 选地面/墙/桌面工作平面 → 拖矩形，显示实际 a×b 格 → 沿法线拉高 c 格，显示将填充的格数 → 命名并提交 → 选物体整件摆放，或切到格子/区域模式加格、挖空 → 保存与撤销。

| 模式 | 操作 | 必须给用户的反馈 |
| --- | --- | --- |
| 查看 | 旋转、缩放、切换平面/剖切高度 | 不触发绘制；可辨证据、推断、用户设计 |
| 物体 | 点击选择、整格移动、复制、90°旋转、改名/锁定 | 选中范围、承载面、尺寸与占据同步 |
| 创建区域 | 承载面框矩形，再拖高或输入 a/b/c | 预览实际占据，冲突格/未知区提示，Esc 取消 |
| 单格/区域编辑 | 指向格面添加邻格，删除命中格；选区填充/挖空 | `(level,i,j,k)`、owner、实际新增/删除数；面合并后仍可操作 |
| 局部变密 | 将选区吸附为对象局部完整父格集合，再 h/2 拆格 | 显示实际 ROI；米制形状、标签和支撑不变，未选父格逐值不变 |
| 语义细化 | 指定粗框“做成柜子/冰箱/花洒”，预览新部件 | 增加了哪些结构、哪些是设计推断；保留粗版并可撤销 |

“贴墙摆放”和“在墙上建东西”用工作平面与法线；空中定位用高度/切片或明确的第二阶段高度手势，不强迫用户用透视猜深度。地面和墙默认锁定，桌面承载物随父件移动；不能通过移动父件绕过对子件的锁定。

## 平整和细化的不同职责

平整从语义分类开始。墙地面使用理想平面/洞口约束；桌面是推断的支撑面；家具粗框是范围；用户新增物体是设计。扫描点只能在限定语义区域内提供有界拟合和差异提示。平整不是对整个 occupancy 反复做平滑、膨胀/腐蚀；那会吞掉开口、磨掉直角和串联相邻物体。

**拆格只改变表达精度**。一个实心父格确定性分成 8 个实心子格，外形、体积和标签不变。它不会凭空得到柜门、隔板或把手。

**语义细化增加几何结构**。在已命名粗范围里用 Box/Cylinder 等部件形成柜板、门、隔层、把手，再确定性栅格化。先做人工/确定性部件候选验证局部规则，再交给 AI。空包围盒里的候选可以激活新的局部父格；不能因为旧粗格未占用，就永久禁止生成细腿/薄板。最终仍不得越出选区、破坏支撑或改锁定面。

VoxLution 对这里有价值的是“先布局/粗层，后按局部与邻界补细节”，不是训练好的模型直接用。论文也承认会继承扫描噪声；我们的平面锁定、局部范围和非破坏编辑需自己实现。它的离线整房生成速度不能作为浏览器交互延迟。

## AI 接入和原版 Skill 继承

先用 openPlan3D 已有 MCP 验证读项目、改单件家具和一次撤销；这只是接缝验证，体素功能完成后再扩展工具。不把每个 cell 通过现有最多 500 ops 的家具接口提交。

新增 `get_region`、`preview_voxel_edit`、`commit_voxel_edit` 一类受限操作。请求含 sceneRevision、选区、owner、锁定承载面、邻块边界和分辨率；模型输出部件树/区域操作，由本机确定性执行器编译为 chunk patches。先验证完整事务再提交，一次 AI 动作进入一次撤销；旧版本、非法或越界提案不部分写入。现有全项目 JSON clone/Undo 和整层签名重建不能直接承担高频体素编辑。

完整保留 scan-to-threejs 的 Measure→Model→Compare 及脚本和许可，再叠加 voxel 契约；完整保留 openplan3d-plan-authoring 的单位、验证器、导入规则及引用文件。不要只摘抄几段 Skill，不让任何上游交付指令回写 reference。生产 Bridge 的浏览器/server dev 开关还需统一验证；有 MCP 源码不等于已经接通我们模型。

## 实验 7 的硬验收

- 创建 3×2×2 = **12 个真实占据单元**，命名后可整体摆到桌面；删一格=11，撤销=12。导出/重载后占据哈希与语义相同。
- 在这 12 格中只选 1 格做 h/2，得到 **19 个叶占据单元**，总占据体积不变，另外 11 个父格逐值不变。边界裁格另测，不能套用完整立方体的计数公式。
- 上例删一个子格为 18；再全局 h/2 为 95 个占据格，孔保留，缺角父格不能有损合粗。首版任意框选先对齐完整父格并显示实际 ROI。
- 对整个 12 格体积变为 h/2 / h/4，完整无裁剪时分别为 96 / 768 格。米制位置、外包络、支撑与标签不动，墙面和洞口也不变。
- 先挖一个孔，再全局变密/尝试变粗：孔不能被粗代理重建填回。选择与编辑使用真实格子查询；关掉格线仍可操作。
- 保存、撤销/重做、Worker 竞态、负坐标和恰在边界的拾取、粗细交界、锁定父/子件、门窗开口、选区外不变均有确定性测试。
- 物体实例不因接触被合并、不因断片被拆散；原始 sourceInstanceId、人工拆合/归属和 unknown/conflict 状态往返保存保持。
- 2×2×2 挖一格后移动/90°/重载仍七格且孔随物体走；0.73 m 桌面建格不改桌高或漂移局部 origin/pivot。厚度0.1 m的1×1 m墙板挖0.5×0.5 m贯通洞口后体积0.075 m³，穿洞射线不命中。
- 真实浏览器从输入手势走通创建→摆放→加/删格→挖空→局部拆格→撤销→保存重开；不能只通过内部 API 写状态来冒充鼠标操作。
- 记录主力设备、浏览器、分辨率、可见/占据格数、draw calls、内存、帧时间与编辑/撤销延迟。10k/100k/1M 格分档实测，超预算需阻止或分批，不能给未经测量的“实时”承诺。

对应自动任务：P2-00 框架/适配 → P2-06 精简工作台/统一事务与保存 → P2-05 实例/候选边界与代理纠错 → P2-01 真占据 → P2-03 游戏式格/区/物体编辑与实际归属修正 → P2-02 局部层级 → P2-04 增量性能/历史验收。随后 P3 接真实 AI。研究完成不等于上述任务已完成，本轮不改变实验 6 的能力声明。
