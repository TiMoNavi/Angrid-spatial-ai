# 实验 2：从 ZIP 到可编辑初稿的处理记录

页面中的五站既是处理流程，也是**状态记录**。前四站已由脚本或网页执行，第五站仍未完成。每份扫描单独转换；目前不把同名的两次办公室扫描当作已自动对齐的一间屋。

## 本次已执行

1. **解包核验**：只读打开 `~/Downloads/Office.zip` 与 `~/Downloads/Office 2.zip`，核对 `manifest.json`、`room-0.json`、照片/深度帧索引及可选 PLY。原始 ZIP 没有改写。
2. **米制坐标转换**：调用作者技能中的 `bundle_to_room.py`，将 RoomPlan 的表面中心/尺寸/方向转为 `polygon`、`walls`、`openings`、`objects`、`photos`。墙的 `u0/u1`、`v0/v1` 指明墙面上的窗洞；地面取 y=0，单位米。第一包平面外接范围约 4.52 × 3.16 m；第二包约 2.83 × 2.60 m。这是识别外接范围，不是精确施工尺寸。
3. **保留视觉证据**：抽取照片样本及一帧原始 RGB/深度对；对 12 帧深度按 `X=(pixelX-cx)×d/fx`、`Y=-(pixelY-cy)×d/fy`、`Z=-d` 投影，再乘相机到世界的矩阵。点图只用于解释深度数据；第二包原始 PLY 原样另存。
4. **生成结构粗模**：实验 3 读取 `converted.json`，在浏览器建立地板、带窗洞的墙和按物体识别框组合的桌椅柜。可交互，但家具形状和材质仍是示意。

可重复命令，从 `experiment/` 运行：

```bash
.venv/bin/python tools/prepare_data.py
python3 -m http.server 5189 --bind 127.0.0.1
```

准备脚本入口在 `../tools/prepare_data.py`；每包转换原始输出在 `../.private/<office-1|office-2>/converted.json`，命令输出在 `conversion.log`。页面提供按阶段点击/方向键切换和两份包切换，可以检查每一步对应的实际资产。

## 仍需做的工作

要达到作者示例办公室那种可辨识且写实的效果，还需逐件根据照片与原始网格修墙面、家具轮廓、开口、材质比例和真实灯具位置。具体做法是用照片记录的相机位姿渲染**同机位**网页截图，叠图比对误差，再反复调整。当前实验没有完成同机位校准、跨会话配准、纹理照片投射到网页粗模或高斯训练，页面因此不展示假造的“处理后照片级对比”。

作者提供的 `scan-to-threejs` 是一份**给编码代理的步骤说明和脚本工具箱**：解析扫描包、保持坐标关系、建立可编辑 Three.js 房间、用同机位照片比较并迭代。它并不是手机上的“自动一键美化按钮”；`bundle_to_room.py` 只完成测量结构的基线转换。依据是仓库内 `reference/3d-model-anything/.agents/skills/scan-to-threejs/SKILL.md` 及其 `references/modeling.md`。
