# 实验 4：扫描结果怎样变成可编辑的体素网格

前三个实验分别回答了扫描包里有什么、怎样转换成米制结构、网页怎样渲染结构。这里验证下一步：**把真实扫描的表面证据放进可调密度的房间网格，同时把 RoomPlan 家具识别框变成可检查的粗家具体量**。两条结果并列显示，不能把扫描点落入的格子直接称为已识别家具。人工修改与新增家具留待后续交互实现。

## 数据边界

- 房间坐标沿用实验 2 的 converted.json：单位米，地面 XZ、Y 向上。以后接 XY 地面/Z 向上的编辑器或 AR 时，要显式保存坐标变换。
- **第一份没有导出的 PLY，不等于只有 12 帧稀疏点。**原包有 434 帧完整的 256×192 深度、置信度、内参与位姿；12 帧只是实验 1 的轻量显示抽样。第二份有 274 帧同类深度，另有 98,553 顶点、176,922 面的原始 LiDAR PLY。两次扫描是独立会话，不自动拼接。
- 两份都应从**全部深度帧**提取有效深度落点，按相机位姿与实验 2 的 worldToRoom 进入房间坐标，再累积到网格。每帧可以规律抽样像素以控制成本，但不能把抽样帧误称为全部数据。第二份的原始 PLY 作为另一条表面证据与深度体素交叉检查，而不是第一份唯一的替代品。
- RoomPlan 的家具类别、中心、尺寸和朝向可生成**扫描推断的粗家具占位**，与原始表面分层保存；这不是从杂乱 PLY 自动识别、封闭并精细重建家具。
- 单靠表面点不能断言其余格子已观测为空。没有逐射线的空闲证据时，未落点的格子保持未知，不能用作家具净空保证。
- 网格边长只改变方块表达；家具中心、尺寸、朝向和房间原点始终以连续米制数值保存。改密度时重新采样，不能累积量化误差。

## 要看到的交互

选择扫描会话和格子边长，默认显示原版 TSDF 融合网格的表面体素，可切回着色三角网格原貌或全帧深度归并点；第二份还可切到筛选后的原包 PLY。叠加 RoomPlan 粗家具及房间边界，点击家具查看标签、米制尺寸、朝向和来源。观察截面只隐藏一定高度以上的扫描表面，不改变源数据或格数。显示参与深度帧数、有效采样数、格数和密度成本，避免把方块数量误当作实心体积或精度提升。

实验 4 的完成线是可复现的“扫描证据 → 有来源的网格 → 粗家具”的可视化与核对。后续产品再加入人工修改方块、成组打标签、在地面拖动和高度调整、局部 AI 细化、AR 半透明回看。AI 只细化用户选中的单件物体，摆放由人决定；AR 回看复用米制房间坐标并要求重定位。

## 体素接在哪一层

本次实际执行的主路是：

```text
原始 ZIP 的全部深度 + 置信度 + 内参 + 位姿
  → 原版 reconstruct_bundle.py，2 cm TSDF 融合
  → scan_world.ply
  → 原版应用 worldToRoom 一次
  → scan_room.ply / scan_room.glb，单位米、Y 向上
  → 实验 prepare_mesh_voxels.py
  → 按三角面 / 格子相交生成 20、10、5、2.5 cm 表面格
  → 网页对照着色网格原貌与规则化表面格

converted.json 的 RoomPlan objects
  → 连续米制中心、尺寸、朝向、类别
  → 独立的局部家具框网格
  → 与扫描表面叠加核对，之后再做人工修正与布局
```

第二包还走一条独立参照路：原始 `raw-mesh.ply` → 只保留 `inroom=1` 的顶点及全部顶点均保留的三角面 → 应用同一包的 worldToRoom → `mesh-voxels/raw-room.ply` → 同样的三角面表面体素。原始 98,553 个顶点中 81,244 个标记为当前房间，筛选后保留 147,149 个三角面；未把旧房间几何当成本次房间的证据。

完整深度投影归并点也保留为诊断路。它处理全部帧，每 4 像素取样，先归并到房间坐标中的 2.5 cm 基本网格；颜色表示重复落点，不是照片颜色。深度/置信度门限与 TSDF 对齐为最大 3.5 m、置信度 ≥1，但投影归并没有做 TSDF 的表面融合，采样数量和输出形态仍不相同，不能称为同一算法的质量评分。

必须区分两个格子尺度。TSDF 的 2 cm 是上游重建参数；网页的 20 / 10 / 5 / 2.5 cm 是下游表达尺度。切换网页密度不重新移动家具、不重设房间坐标，也不把上一次体素结果继续缩放。家具边界格按真实尺寸裁短，原始中心、尺寸和朝向保留，细格不会恢复缺失的观测。

三角面表面格只表示网格经过的位置。RoomPlan 家具框中的“占位格”只表示语义边界框。两者都没有证明物体是封闭实心，也没有证明其他格子已观测为空，不能直接用于净空或安装保证。

## 本次真实运行结果

原 ZIP 与 reference 保持只读，完整依赖提取至 `.private/<scan>/reference-source/Room`，全部生成物只写入 Git 忽略的 `.private/`。直接投影与原版融合分别处理全部帧。原版使用 Open3D 0.19.0、NumPy、Pillow；参数为体素 2 cm、最大深度 3.5 m、置信度 ≥1、TSDF 截断宽度 8 格，不做面数简化。

| 原版重建输出 | Office.zip | Office 2.zip |
| --- | ---: | ---: |
| 全部深度帧 | 434 | 274 |
| 原始照片 | 56 | 37 |
| 着色候选视图（原照片 + 深度 RGB） | 490 | 311 |
| 清理后顶点 | 225,146 | 227,520 |
| 清理后三角面 | 449,622 | 456,833 |
| 获得颜色的顶点比例 | 81.5% | 77.9% |
| 本机脚本报告耗时 | 49 秒 | 43 秒 |

未获得颜色的顶点保留灰色，不用生成纹理掩盖。相机覆盖率只描述着色来源，不是尺寸精度、扫描完整度或最终家具识别率。

| 表面体素尺度 | 第一包 TSDF 网格 | 第二包 TSDF 网格 | 第二包原 PLY（inroom） |

直接投影路在候选房间范围内分别累积 1,189,218 / 723,491 个采样落点，归并成 203,565 / 156,495 个 2.5 cm 表面格。与融合后的表面格差异包含噪声、观测厚度、清理和采样方法等因素，格子更多不等于更准确。

原版结果保存在 `reference-depth/reconstruction.json`、`scan_room.ply`、`scan_room.glb`；包装层另写 `reconstruction.log`、`run-config.json`（含原版脚本 SHA-256）。实验新增的 `mesh-surface-grids.json` 和 `mesh-voxels/raw-room.ply` 明确属于适配层。复现命令见 [实验 README](../README.md)。

## 验证与当前边界

纯几何核对已覆盖两包四档网格的原点、维数、唯一格键与范围，以及每件家具在不同密度下的连续米制边界。浏览器只绘制最多 70,000 个表面实例；超过时界面明确提示抽显，完整格数与缓存不变。家具框只渲染外壳以避免内部无用面，框占位统计仍包括内部。

实际浏览器检查覆盖两包共 20 种来源/密度组合、着色网格原貌、家具选择、图层开关、截面高度、快速切换扫描，以及 375 px 手机视口与减少动态效果设置；检查通过，无页面脚本错误或请求失败。原貌与表面格采用相同候选房间范围和观察截面，统计仍取完整高度。Open3D 的双精度 PLY 属性仅在浏览器上传 WebGL 前转为 Float32，磁盘原版输出不改写。

另用单个合成三角面验证体素适配器覆盖三角形内部，而非只采三个顶点或填满三角形外接盒；未相交高度保持未标记。两包 scan_world 与 scan_room 顶点逐一核对，确认对应关系确实是各自 worldToRoom 的一次变换。这是程序变换一致性检查，不代表真实房间达到数值计算的小数精度。

当前实现完成扫描原貌、体素表面和 RoomPlan 框的核对。尚未实现用户创建/编组方块、改标签、拖放家具、撤销、AI 单件细化或 AR 重定位；也未做跨会话配准。下一步应在当前米制对象结构上加编辑与来源记录，不必改原版参考工程。
