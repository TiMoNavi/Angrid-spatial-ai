# Angrid 技术路线与 3D Model Anything 基线架构分析

核对日期：2026-11-13。本文以 [本仓库的上游快照](../reference/README.md)及已有 iPhone 15 Pro 真机扫描为基础，把**已存在的能力**和**Angrid 接下来要开发的能力**分开。基线快照对应上游提交 31b2dc9，另含四处本地编译/网格修复；两次真机扫描中的第二次产出 37 张照片、274 帧深度、98,553 个网格顶点和 176,922 个三角面。这证明文件链路可用，不证明尺寸精度、长时间稳定性或跨次重定位精度。

## 1. 基线并不是单个 App：它的层次结构

```text
reference/3d-model-anything/
├── apps/house-capture/             iPhone 原生扫描与房屋/房间管理
│   └── HouseCapture/               SwiftUI + ARKit + RoomPlan + 导出
├── .agents/skills/scan-to-threejs/  扫描包转换、量测、建模、照片比对工作流
├── apps/room-viewer/               Vite + Three.js 浏览器展示与比对
├── packages/room-runtime/          RoomModule 类型、墙/材质/灯光/渲染积木
├── packages/room-physics/          已建模场景的 Rapier 交互物理
├── demos/                          手写的场景模块；当前注册 office-v4
└── data/                           办公室示例测量/素材；私人采集另放忽略目录
```

| 层 | 关键入口 | 真实职责 | 对 Angrid 的意义 |
| --- | --- | --- | --- |
| iPhone UI/编排 | [HouseCaptureApp.swift](../reference/3d-model-anything/apps/house-capture/HouseCapture/HouseCaptureApp.swift)、[CaptureScreen.swift](../reference/3d-model-anything/apps/house-capture/HouseCapture/CaptureScreen.swift)、[CaptureController.swift](../reference/3d-model-anything/apps/house-capture/HouseCapture/CaptureController.swift) | 房屋/房间界面、扫描状态、同一个 ARSession 与 RoomCaptureSession 的生命周期 | 作为新扫描 App 的起点，保留现有追踪/失败处理 |
| 传感器/扫描 | [ScanView.swift](../reference/3d-model-anything/apps/house-capture/HouseCapture/ScanView.swift)、[CoverageEngine.swift](../reference/3d-model-anything/apps/house-capture/HouseCapture/CoverageEngine.swift) | 获取 ARMeshAnchor、照片、采样 RGB-D，预览覆盖度并保存带三角面/面分类的 PLY | 实时点云与网格增量应在这里接出，而不是从导出 ZIP 反推“实时” |
| 坐标/重定位 | [HouseProject.swift](../reference/3d-model-anything/apps/house-capture/HouseCapture/HouseProject.swift)、[Relocalization.swift](../reference/3d-model-anything/apps/house-capture/HouseCapture/Relocalization.swift) | house → zone → session → room；保存 ARWorldMap，继续扫描时重定位并检查旧/新网格一致性 | 在现有坐标链上定义稳定的房间相对位姿与定位状态 |
| 持久化/共享 | [ScanBundle.swift](../reference/3d-model-anything/apps/house-capture/HouseCapture/ScanBundle.swift)、[HouseStore.swift](../reference/3d-model-anything/apps/house-capture/HouseCapture/HouseStore.swift) | 写 manifest、RoomPlan JSON/USDZ、网格 PLY、照片、深度、位姿与 ZIP | 增加连续轨迹、语音标签和实时流版本号，保留原始证据 |
| 离线转换 | [scan-to-threejs/SKILL.md](../reference/3d-model-anything/.agents/skills/scan-to-threejs/SKILL.md)、[bundle_to_room.py](../reference/3d-model-anything/.agents/skills/scan-to-threejs/scripts/bundle_to_room.py)、[house_to_rooms.py](../reference/3d-model-anything/.agents/skills/scan-to-threejs/scripts/house_to_rooms.py) | 选房间/对齐会话，转房间局部 JSON、照片，提供测量与截图比对脚本 | 可改造成独立、可测试的导入层；脚本不是自动装修系统 |
| 网页展示 | [room-viewer/src/main.ts](../reference/3d-model-anything/apps/room-viewer/src/main.ts)、[room-runtime/types.ts](../reference/3d-model-anything/packages/room-runtime/types.ts)、[demos/index.ts](../reference/3d-model-anything/demos/index.ts) | 加载已编写的 RoomModule，提供旋转/漫游、平面图、扫描/模型叠加与视觉比较 | 可复用渲染框架，但需另做数据驱动的扫描检查和用户编辑器 |
| 物理试玩 | [room-physics/physics.ts](../reference/3d-model-anything/packages/room-physics/physics.ts)、[play/main.ts](../reference/3d-model-anything/apps/room-viewer/src/play/main.ts) | 对已手工建模的物体提供 Rapier 交互 | 不能把它当作已验证的扫描网格碰撞求解器 |

**当前实际数据链：** iPhone 同会话采集 → House Capture 房间/会话 ZIP → 解压到被 Git 忽略的本地采集目录 → 转换脚本整理 RoomPlan 和照片位姿 → 人工或 Agent 根据测量、照片编写 `demos/<room>/index.ts` 的 RoomModule → 在 `demos/index.ts` 注册 → Viewer 展示并做按原照片视角的比对。转换能给出测量基线，**不会自动生成精细可编辑房间**。当前公开 office 示例没有原始扫描照片，Scan/Overlay 参考层因此关闭；Vite 热更新也不是手机到 Mac 的实时传输。

## 2. 用户需求与现有代码的差距

| 需求 | 基线已有 | 需要新增或验证 |
| --- | --- | --- |
| 实时房间相对位姿 | ARKit 当前位姿、临时 UI 位姿历史、house/zone/session 变换、ARWorldMap | 持久化完整轨迹事件；显式 room frame、跟踪与重定位质量；重开 App 后成功重定位才发布有效 room pose |
| 实时轨迹与画面 | 带时间戳和内参的采样照片/RGB-D；控制器给 UI 的位姿更新 | 与轨迹同步的持续预览视频/帧流、丢帧报告、可回放索引；不把采样帧称作完整连续视频 |
| 实时粗彩色点云 | LiDAR mesh 与照片覆盖预览；离线可由 RGB-D 生成点云 | 从深度/图像/位姿增量生成带预算的粗云，按房间坐标保存/传输变化；静态清理留给后处理 |
| 网格/碰撞候选 | ARKit 三角网格实时显示，最终 PLY 有面索引和分类 | 网格修剪、开口/未知区处理、简化碰撞体、误差复核；不能直接拿原始 PLY 判断家具一定放得下 |
| 扫描后 3DGS | 有照片、内参、位姿、深度与初始化几何 | 由同一采集包生成训练输入，在 Mac 或授权的端侧管线训练；模型与 room frame 显式配准 |
| 房间包围盒/语义/切分/规整 | RoomPlan 墙门窗家具、ARKit 面分类 | 从经过复核的碰撞几何求整体范围和 AABB/OBB；物体实例、规则墙地面、去噪/降面标注来源与置信度 |
| 语音空间标签 | 无 | 按键入口、麦克风/识别权限、当前相机射线与命中几何、草稿/定位/人工确认状态 |
| Mac 实时查看 | AirDrop/Files ZIP；网页离线展示 | 发现/配对、实时事件流、可靠文件传输、Mac 桥接服务和网页数据驱动检查视图 |

基线的画面/深度是按运动与质量选择的采样数据，不是每帧保存。控制器给 UI 的相机位姿约 15 Hz，临时位姿历史只有最近一段；要满足“自身轨迹和画面”，必须建立专门的时间线记录，不能只延长界面数组。Pixel-UMI 的可视化参考是“静态点云 + 相机轨迹 + 同步视频”；其干净点云经过离线校正与动态筛选。Angrid 实时粗云与最终高质量点云应分别存档和标注。

## 3. 建议的产品分层与数据契约

保留 `reference/3d-model-anything` 为可追溯快照；产品代码随后从其 iPhone/Viewer 能力提取到独立目录，而不是在参考快照中持续堆产品功能。拟议模块（**目前尚未创建**）：`apps/iphone-capture`、`apps/web-editor`、`apps/mac-bridge`、`packages/scan-contract`、`packages/geometry-validation`。最初可以少拆包，但保持边界：扫描事实、处理推断、渲染资产、业务规则分层。

```text
iPhone ARKit + RoomPlan
   ├─ 本机实时预览：位姿 / 画面 / 粗云 / mesh / 语音标签
   ├─ 可恢复的扫描包：原始帧、语义、网格、世界地图、时间线
   └─ 可选局域网事件流 ──> Mac bridge ──> 网页扫描检查视图
                                  │
                              扫描后处理
                                  ├─ room.json + 简化碰撞体 + 标签/物体
                                  └─ 3DGS 写实资产
                                       ↓
                           网页编辑器 / 人工复核
```

数据包至少定义 `schema_version`、`house_id`、`zone_id`、`session_id`、`room_id`、时间基准、米单位、轴向、图像内参、每帧相机位姿、跟踪状态、RoomPlan 元素及置信度、网格顶点/面/类别、标签和文件校验和。源文件、人工修订、算法推断与训练模型分别保存。实时事件建议至少有 PoseFrame、PreviewFrame、CloudDelta、MeshDelta、VoicePin、TrackingState；每条事件包含单调序号和坐标版本，断线后可恢复。

基线的 ARKit 会话以米和 +Y 向上表示。HouseProject 已保存 session→zone→house 的变换。Angrid 需再定义确定的房间坐标；先把 RoomPlan 地面/墙确定为候选，记录其到 session 或 house 的变换。房间相对相机位姿是 `T_room_camera = inverse(T_world_room) × T_world_camera`。坐标尚未确认或跨次对齐失败时，不向下游发布“已定位”的姿态。多房间/跨会话不能靠房间名称或时间顺序硬拼；需用 ARWorldMap、几何配准和误差检查明确状态。

## 4. iPhone 实时链路的实施要点

1. **位姿与恢复。** 在 ARFrame 更新时记录时间戳、位姿、内参、tracking/mapping 状态及 room 坐标版本，形成可持久化的轨迹；前台界面与可选 Mac 流从同一事件源订阅。保存世界地图不等于关闭后仍追踪：App 进后台会中断 AR，相机重开时用 initialWorldMap 尝试重定位；只有跟踪恢复 normal 且与保存场景核对通过，才恢复房间相对位置。基线已有 [重定位与网格残差检查](../reference/3d-model-anything/apps/house-capture/HouseCapture/Relocalization.swift)，可以沿用并补量化验收。
2. **画面与粗云。** 将低分辨率预览画面与位姿按时间戳配对；保留原始采样照片/RGB-D。用置信度合格的深度像素反投影、图像取色、位姿变换和体素融合形成有内存上限的粗云；视口按需渲染相机视锥、轨迹与已观测/未知区域。跨帧静态筛选、位姿精化和高质量融合放到扫描后处理。根据发热和内存动态降采样，不预设固定帧率或点数。
3. **网格与碰撞。** 继续用 ARMeshAnchor 做低延迟扫描反馈；按 anchor ID/版本发送增量而不是重复推送全屋 PLY。保存原始面分类与拓扑，另从 RoomPlan 墙/地/门洞和经清理的 mesh 生成参数化 collider。首次范围包围盒基于清理后的房间 collider，辅以 RoomPlan 边界交叉检查；噪点、未观察区域和开口不能默默填成实体。
4. **可复核性。** 每个语义、点、网格面和碰撞体至少能追到扫描会话/传感器或人工编辑；录制丢帧、重定位失败、空网格和坐标跳变应在 UI 与 manifest 中可见。基线首扫曾产生空 PLY，本地补丁后第二次才得到非空网格，因此“文件存在”必须与顶点/三角面/覆盖量一起验收。

## 5. 语音标签与操作按钮

“长按功能侧键”先按 iPhone 左侧 **Action Button（操作按钮）**理解：App 提供“添加空间标签” App Intent / App Shortcut，由用户在 iOS 设置中把快捷指令分配给按钮；App 内也保留大按钮。Apple 的 [Action Button 指南](https://developer.apple.com/design/human-interface-guidelines/action-button)描述的是系统触发已配置的动作，不能按普通按键事件直接拦截。若特指右侧电源 Side Button，Apple 的[第三方语音入口](https://developer.apple.com/documentation/appintents/launching-your-voice-based-conversational-app-from-the-side-button-of-iphone)有地区与专用 entitlement 限制，不应作为中国部署的默认入口。

交互为：唤起前台语音框 → 检查麦克风/语音识别授权 → 显示当前画面并提示对准目标 → 等待有效 room 定位 → 用相机中心射线命中 RoomPlan/网格/深度 → 保存“这是插座”等文字、音频引用、时间、相机位姿、命中点/面、房间 ID、跟踪质量和人工确认状态。若未重定位，先存语音草稿，待重新对准并确认后再附着坐标。离线语音仅在所选设备/语言的 [supportsOnDeviceRecognition](https://developer.apple.com/documentation/speech/sfspeechrecognizer/supportsondevicerecognition) 为真时启用；失败可改手输或在获准情况下使用联网识别。

## 6. Mac 通信与网页分析端

第一版优先完成扫描包导入，确保断网也能工作。增量同步可以采用 iPhone 与 Mac 的局域网发现、配对和可靠连接：控制/位姿/标签走小事件，预览画面压缩并限速，点云和网格按增量发送；完整照片、深度与训练包按块、校验和与断点续传。Mac 侧桥接服务把同一会话事件提供给本机浏览器；网页断线显示最新已知状态而非假装持续实时，重连后按序号补齐。网络时延、无线直连方式和 USB 备选都需实测，不预设 10 ms 保证。

网页端应分三层发展：**原始扫描检查视图**展示 RoomPlan、原始/简化网格、粗云、轨迹、相机画面和现场语音点；**处理/审阅视图**检查 3DGS 与结构、碰撞体、物体分割的坐标和来源；**装修编辑视图**才允许拖放家具、比较布局和记录人工确认。现有 [room-runtime](../reference/3d-model-anything/packages/room-runtime/types.ts) 的 RoomModule/渲染组件可复用；现有 [room-physics](../reference/3d-model-anything/packages/room-physics/physics.ts) 只是手工场景物理原型，商品适配和通道/门扇校验需独立、可审计的几何规则层。网页也不能把 Vite 热更新当作实时手机数据连接。

## 7. 扫描后处理与顺序

- **结构先行。** 从 RoomPlan 生成墙、地、开口与对象框，结合面分类 mesh 去噪、裁剪、降面；建立房间完整度/未知区与尺寸抽样核对。输出稳定的 room.json、简化 collider 和整体 AABB/OBB，记录它们来自何种数据。
- **语义与实例。** 首版以 RoomPlan 的墙/门/窗/物件为已知候选，允许工作人员用语音标签修正；更细物体分割/自动命名在真机数据集和人工标注上验证后再加入。
- **写实资产。** 同一会话的照片、内参、位姿、深度可交给 Mac 训练 3DGS，再将模型对齐到 room frame。Splatify-Anything 是端侧技术参考，其现行源码为非商业许可；若要直接集成，须另行取得相应授权。高斯与碰撞体分开存储和显示。
- **原始产品构想。** 适老化问答、A/B 布局、设备/门扇/水电接口校验及施工辅助应建立在上面的结构和证据链上，输出置信度及人工复核状态。扫描模型和自动路径不能直接当作施工图或“100% 可安装”保证。

**下一轮可执行验收：** ① 用已有真实第二次扫描在独立转换器里核查语义/网格/照片/深度及重投影，并用卷尺测数段墙/门洞；② 在同一房间测试关 App 后重定位、失败恢复与位置误差；③ 完成粗云/轨迹与语音标签的本地存储，再做 Mac 网页实时预览；④ 用同一批照片试训 3DGS，检查模型相对房间网格的方向、尺度、遮挡和发热/耗时。每一步分别记录成功样本、失败样本和误差，别用单次演示代替稳定性结论。
