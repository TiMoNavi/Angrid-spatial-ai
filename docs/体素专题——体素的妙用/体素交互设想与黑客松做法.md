## 我的理解对不对

整体方向成立。粗体素先让人看懂房间和家具的体积，人用游戏式操作确定位置，AI 只补选中物体的形状，最后回真实房间看半透明叠加。这是一条适合黑客松演示的完整路径。下面几处概念要分清，做出来的画面才不会误导用户。

| 原文中的想法 | 判断与需要补上的条件 |
| --- | --- |
| 扫描房间和家具，再划成密度可调的网格 | 可行。房间包围盒负责限定编辑范围，墙和门窗仍需单独保留。把格子边长 s 作为用户可调参数，界面显示厘米单位。格子变密会增加数量，也会改变方块预览的形状。房间尺寸、家具尺寸和摆放位置始终另存为米制连续数值，改密度时从原始几何或基本图形重采样，不能让已摆好的家具跳位。 |
| 混乱扫描归一化为体素家具 | 体素化只能得到哪些格子有扫描表面；它不能自行判定一团网格究竟是一张床、两把椅子，或尚未扫到的空处。黑客松版借助 RoomPlan 给出的家具类别和尺寸框建立粗家具，再让用户改标签、边界与朝向。原始扫描保留为背景和检查依据。Apple 对 RoomPlan 的说明也只承诺识别的家具类型及尺寸等参数化结果，不能把它当作精细家具模型。[RoomPlan 介绍](https://developer.apple.com/augmented-reality/roomplan/) |
| 像游戏一样造方块、打标签并拖放 | 很适合首版。几个方块先组成一件物体，再给这一组一个名称。标签属于物体实例，不需要逐格填写。扫描得到的旧家具与用户新放的家具用不同颜色和来源标记，避免把设计方案认成已存在的实物。 |
| 斜视图先在 XY 拖动，再沿 Z 调高度 | 交互上顺畅。可以规定编辑器的 XY 是地面、Z 是向上，拖动时先与地面平面求交，再用竖直手柄或数值控制高度。当前 iPhone 基线所用 ARKit 是 Y 轴向上，地面落在 XZ 平面；导出 AR 时必须有明确的坐标变换，不能直接把编辑器的 Z 值塞进 ARKit 的 Z 轴。[ARKit 坐标说明](https://developer.apple.com/documentation/arkit/understanding-world-tracking) |
| AI 按体素包围盒局部细化，参考 VoxLution | 思路对，论文用多级稀疏体素逐步预测更细的占用，并照顾相邻块边界。它研究完整场景生成，现有公开资料没有可直接接入的官方实现。黑客松先让 AI 输出选中物体内部的一组小方块或基本几何，再做程序校验；这是借鉴粗到细的思想，并非复现 VoxLution。[论文](论文/VoxLution-arXiv-2610.41501.pdf)与[项目页](https://daoyig.github.io/VoxLution/) |
| 用大模型和 Codex Skill 创建花洒等细节 | 可以让大模型理解“花洒”“靠墙安装”“保留出水头方向”这类文字，再输出受约束的部件参数或体素操作。Skill 是供代理执行的指令、脚本与资料包，可约定生成和检查步骤；它本身不是训练好的三维细化模型，也不自动成为 App 内的推理服务。产品运行时仍需一个明确的模型调用或本地规则程序。[OpenAI 的 Codex Skill 文档](https://developers.openai.com/codex/skills) |
| 布局完成后再对齐回真实房间 | 要保留扫描房间的原点、轴向、米制尺寸和变换，摆放结果直接存进这个房间坐标。这样 AR 阶段是在重用坐标，不是从体素里恢复扫描时丢掉的精度。若重开 App，需先让 ARKit 重定位；失败时由用户对照房间角点手动校正，并显示未确认状态。[Apple 的世界地图保存与加载说明](https://developer.apple.com/documentation/arkit/saving-and-loading-world-data) |
| AR 看半透明柜子，判断实物能否放下 | 很适合展示预期位置和体积，也能发现明显的方向或高度错误。半透明叠加只是视觉比较。真实柜子是否放得下，还要核对产品长宽高、柜门开启空间、墙体和未扫描区域；黑客松演示只给出“视觉对照与待确认净空”，不作安装保证。 |

## 系统建议的做法

### 1. 从扫描得到可信的房间参照

用现有扫描包里的 RoomPlan 墙、地面、门窗和粗家具框确定房间坐标与包围盒，ARKit 网格作为原始表面参考。屏幕上并列显示扫描网格和规则化后的粗框。给每件扫描家具标记“扫描推断”，用户可改名称、粗框与朝向；没有把握的区域显示“未确认”。首版只需桌子、沙发、床、柜子等少数类别，没识别出的形状允许用户用方块手动补。

这里的“归一化”落在可解释的粗家具上。可以先去掉孤立噪点，把同一家具附近的格子归组，然后让用户看着原始扫描确认；扫描表面、RoomPlan 粗框和用户修订分别保存。无需把扫描网格自动变成一套精细、完美的体素家具。

### 2. 建立密度可调的方块编辑器

房间交互网格用边长 s_room 表示，例如演示时提供 10、5、2.5 厘米三个档位，默认值只作为界面起点，实际效果需在设备上测试。斜视图里保留地面 XY 网格、墙体轮廓和扫描参照。用户按住家具或一个方块组，射线与地面相交后在 XY 上拖动；点击“高度”手柄再改变 Z，也可输入厘米数。地面家具默认贴地，花洒等壁挂物先选墙面和挂点，再调离地高度。旋转和格线吸附由用户操作。

“创建方块”与“摆放家具”都要有撤销。新建多个基本立方体后，用户把它们编成一个物体，输入“花洒”“柜子”之类标签。记录物体 ID、来源、标签、原始米制包围盒、局部方块或基本几何、房间中的位置与旋转、所用网格边长。改变 s_room 时重新生成方块显示，保持米制位置与尺寸不动。手动放好的位置不会因细化或改密度而被系统重排。

### 3. 只细化用户点中的那一件

用户点“细化花洒”时，把这件物体的标签、粗包围盒、墙面挂点、朝向和允许修改的局部空间送给生成步骤。只在被选物体内部换用更小的格子，房间交互网格保持原样。黑客松版先提供少数受限部件，例如花洒可由背板、连接杆、喷头和手柄组成。大模型可以为这些部件建议尺寸、排列与更细的体素或基本图形；程序验证输出没有越过包围盒、没有破坏挂点，才显示候选。用户可比较粗版与细版，接受或撤回。物体的房间位置与旋转保持锁定。

若想用 Codex Skill，可把“读取选中物体参数、产出规定格式的局部部件、检查尺寸和挂点、回传预览资产”写成可重复的研发工作流。正式演示前将生成器固定为可调用的服务或本地规则，输出只采用受约束的数据格式。不要让一次自由文本回复直接改房间场景，也不要把 Skill 当作 VoxLution 的模型权重。对于椅子等形状，已有的[DECOR-GAN 与 ShaDDR 分析](体素专题分析.md#ai-只处理选中的家具)可作为后续升级依据。

### 4. 保留坐标，回到 AR 现场核对

编辑器约定 XY 为地面、Z 向上。ARKit 约定 Y 向上。保存一个从编辑坐标到房间坐标的明确变换，再用扫描时保存的房间到 AR 世界变换显示家具。网格边长只决定方块化显示；家具原来的米制位置和尺寸用于 AR 放置。体素细化不会恢复扫描时没采到的尺寸，必要时仍要查看原始扫描或实测。

黑客松最省事的展示是在同一 AR 会话中完成扫描与回看，保留房间锚点。若要隔一段时间重开 App，就尝试载入 ARWorldMap 并等待重定位成功；若失败，让用户在地面和墙角选对应参照点，手动校正平面位置、朝向与地面高度。未完成对齐时先不叠加虚拟家具，也不显示“已确认能放下”。

AR 里用半透明方块显示新方案，描出柜子的外包围范围和贴墙/落地面。用户绕着它看与实物、门口及墙面的关系，点一下可切换扫描粗框、人工方块和 AI 细化版。保存一张同视角前后对比截图即可完成演示。可以报告“视线下看起来有明显干涉”或“当前未看到干涉”；购买和安装前仍应核对真实商品尺寸与净空。

### 5. 黑客松的完成线

一间已扫描房间、两件已识别的粗家具、用户手动放一件新家具，就足以验证这条交互。演示时让用户改一次网格密度，给方块组加标签，先在 XY 拖动，再调 Z；选择花洒做一次受约束的局部细化，确认家具原位置未变，最后到 AR 中看半透明叠加。记录每一步是扫描推断、用户决定，还是 AI 候选。完成线是这条流程可演示、可撤销、能说清误差和未确认之处，而不是生成一间自动装修的房子。
