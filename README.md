# Angrid Spatial AI · 筑语空间

面向居家改造和适老化沟通的空间采集与可编辑房间平台。第一阶段聚焦 **iPhone 在同一次 AR 会话中取得可对齐的房间数据**，让现场人员与 Mac 编辑端理解同一个空间。后续再做写实重建、布局求解、品牌设备匹配与施工辅助。

本项目以 [3D Model Anything / House Capture](https://github.com/wesbos/3d-model-anything) 为技术基线，上游源码、署名和许可文件已保留在 [reference/3d-model-anything/](reference/3d-model-anything/)，复制范围和本地修复见 [参考快照说明](reference/README.md)。该基线能采集 RoomPlan 结构、LiDAR 三角网格、照片、深度、相机位姿和 ARWorldMap；它不自动完成下列全部产品目标。

## 需求范围

| 时机 | iPhone 需要输出 | 第一阶段要求 | 基线与差距 |
| --- | --- | --- | --- |
| 实时 1 | 自身位姿、房间相对位置 | 当前相机到房间的变换及跟踪/重定位状态；保存地图，重新打开后在重定位成功时恢复房间坐标 | House Capture 有 ARWorldMap 和采样位姿；跨次可靠性待实测 |
| 实时 2 | 自身轨迹和画面 | 时间戳对齐的画面、内参、位姿与轨迹，可供现场和 Mac 预览 | 已保存采样照片和 RGB-D 帧；连续视频与高频轨迹流待做 |
| 实时 3 | 粗糙彩色点云 | 从深度、画面和位姿增量形成，显示已观测区域与当前相机视角 | 已有 LiDAR 网格/预览；独立点云增量流待做 |
| 实时 4 | 房间网格/碰撞候选 | ARKit mesh 增量预览，导出带三角面与分类的网格；稳定后生成简化碰撞体 | 已导出三角网格；原始扫描网格不是已验证的碰撞体 |
| 扫描后 | 高斯泼溅数据 | 用同次采集的照片、内参、位姿、深度和点云训练 3DGS；可交给 Mac 后处理 | 基线不训练 3DGS |
| 扫描后 | 房间整体范围与包围盒 | 从经清理的网格和房间结构推导，标注未知区域与误差 | 待实现；粗外接框不可当安装尺寸 |
| 扫描后 | 语义、物体切分、网格规整 | 汇总 RoomPlan/mesh 分类，研究实例分割、去噪、降面、墙地规整和碰撞简化 | 已有部分原始语义；后处理和复核流程待做 |

实时的位姿、轨迹/画面和粗点云借鉴本地 Pixel-UMI 风格示例的 **点云 + 相机轨迹 + 同步视频** 呈现方式。该示例的干净静态点云经离线处理；手机实时粗云只用于预览，不能宣称具有同等精度或自动去掉动态物体。手持 iPhone 的相机视角也不是人的头部视角。

关掉 App 或进入后台时，iOS 不再持续提供 AR 相机位姿。重新打开后加载保存的世界地图，等待 ARKit 成功重定位，再计算 `T_room_camera = inverse(T_world_room) × T_world_camera`；失败则标记“未定位”，不能沿用旧位置。3DGS 是写实视觉层，不代替可查询的三角网格或参数化房间结构。

## 现场语音空间标签

现场工作人员可对准目标说“这是插座”“这里要加扶手”。计划提供应用内按钮和“添加空间标签” App Shortcut；若 iPhone 有左侧 **Action Button（操作按钮）**，用户可在系统设置里将该快捷指令分配给它。第三方 App 不能假定可直接监听任意侧键长按；右侧电源键不是面向所有地区 App 的通用入口。

标签至少保存文本、可选音频、时间戳、房间/扫描会话 ID、当前相机位姿、射线命中点与目标面、定位状态、来源和人工核对状态。从后台唤起时先恢复房间定位，再把语音绑定到空间；定位未完成时只保存草稿，不捏造坐标。语音识别、麦克风和离线语言支持需按设备与系统授权验证。

## Mac 协同与产品方向

先实现可靠的扫描包导出/导入。现有 [room-viewer](reference/3d-model-anything/apps/room-viewer/) 是 Vite + Three.js 离线浏览/照片比对器：需要先转换扫描包，再人工或由 Agent 编写房间模块；它还不是扫描 ZIP 自动生成的装修编辑器。可选实时连接随后发送低频位姿、轨迹、点云/网格增量、语音标签与进度，让 Mac 编辑端看到现场情况；大图像、深度和最终资产用校验和、分块及断点续传。连接断开时手机继续本地采集。无线、USB、时延及带宽都需在设备上验证。

从原始产品构想延伸的后续方向包括适老化多轮沟通、A/B 布局、可编辑家具原语、品牌型号尺寸与接口校验、施工辅助图和 AR 现场交底。它们依赖可测量的房间数据、来源明确的商品参数和专业复核；不是当前已经实现的功能，也不能承诺“100% 放得下”或“零误差施工”。

统一房间数据至少应记录 schema 版本、米单位和坐标轴、房间原点、会话与帧 ID、时间戳、图像内参、相机/房间变换、网格顶点/面/类别、语义来源/置信度和可选世界地图。扫描事实与算法推断分开保存。第一阶段顺序：真实扫描 → 验证数据同坐标 → 恢复定位与语音标签 → Mac 预览 → 扫描后 3DGS。

**状态：** 当前处于需求和基线整理阶段。House Capture 基线已导入，并在本机 iPhone 15 Pro 上完成初步采集；实时粗点云、语音标签、Mac 实时通信、3DGS 及后续装修能力仍待实现或验证。
